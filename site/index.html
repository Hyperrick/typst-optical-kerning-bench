Optical kerning evaluation for Typst

This is an external evaluation artifact for the Typst community. It has two concrete outputs: a reproducible benchmark suite for optical kerning and an algorithm candidate developed from that suite.

The algorithm candidate is `guarded-profile-hybrid`. It is discussion ready, not merge ready: useful for deciding whether this direction fits Typst before anyone proposes compiler changes.

Motivation: Typst already supports metric kerning from font tables. In print, branding, editorial design, packaging, and display typography, an optical option is still often expected when metric kerning is sparse, broken, or visually weak.

The question here is not "should Typst copy InDesign?" It is whether a deterministic, outline-based, cacheable optical kerning method can fit Typst's engineering values.

What to take away

  • The repo is both an evaluation suite and a concrete algorithm candidate, not just a collection of screenshots.
  • The candidate shapes text first, keeps metric kerning as a prior, then applies guarded optical corrections from glyph outlines.
  • The evidence includes Typst metric renders, scripted InDesign Optical baselines, overlays, contact sheets, JSON baselines, and known residual differences.
  • It is not an official Typst project, not a pull request, and not a final API proposal.

Why this exists

Typst already has metric kerning from font tables. That should remain the default. The open question is whether Typst can also offer an optical mode for situations where designers normally reach for layout tools such as InDesign: large headlines, brand typography, packaging, editorial display type, sparse font kerning tables, mixed-case words, punctuation, numbers, and shaped ligatures.

A subjective screenshot is not enough for that discussion. This repo tries to make the question reviewable by using multiple fonts, multiple samples, multiple algorithms, metric parity gates, rendered overlays, and compact baselines.

Status for discussion

The current status is: discussion-ready algorithm candidate. More tuning data can still be added, but the core algorithm direction is now stable: shape text first, use font metric kerning as a prior, compute optical corrections from glyph outlines, and keep the implementation deterministic and cacheable.

This repo is intended as material for an informed Typst community discussion before any implementation proposal exists. It is not a merge-ready patch. The technical details remain in the linked repository documents.

How the candidate emerged

The benchmark did not start with `guarded-profile-hybrid`. Earlier candidates tested nearest contour distance, weighted whitespace profiles, area balance, metric-prior blending, and a conservative fallback-only mode. Those simpler approaches were useful, but each exposed different failure cases: over-tight round forms, apertures, punctuation, script joins, ligatures, or word-level accumulation.

The current candidate keeps the useful parts: metric kerning remains the prior, outline profiles provide the optical signal, and dynamic guards block unsafe moves. That is why the result is a guarded hybrid rather than one single geometric rule.

Possible Typst API shape

Typst currently exposes kerning as a boolean. The benchmark does not settle a public API, but it uses this sketch to make the possible behavior concrete. 

#set text(kerning: true)  // current metric kerning
#set text(kerning: false) // current disabled kerning

// Possible future shape:
#set text(kerning: "metric")
#set text(kerning: "optical")
#set text(kerning: "none")
